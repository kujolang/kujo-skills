# Webops Distribution

## Purpose

Use this skill for creating source-grounded distribution assets and optionally publishing with ACT authority. Its primary sources are Approved published content, Howl, distribution integration, permission receipt, and brand constraints.

## Workflow

1. Confirm source content is approved and published.
2. Derive claims, links, metadata, and channel variants without inventing content.
3. Generate and validate local Howl assets first.
4. Publish only to configured destinations under explicit ACT and retain receipts.

## Required Output

- distribution asset pack.
- source map.
- validation.
- optional publication receipts.

Every output must name target/scope, evidence class, retrieval or run time,
unavailable checks, permission mode, and comparison baseline where applicable.

## Boundaries

Without integration or ACT, stop at local reviewable assets. Preserve OBSERVE/PROPOSE/ACT boundaries, provider cost and credential
limits, stable finding identity, and the distinction among finding,
recommendation, action, and outcome. Never store credentials or fabricate
provider data, rankings, indexing, citations, compliance, or causation.

## Verification

Validate source artifacts with their owning tool before interpretation. Run
the current repository's WebOps cross-reference validation when agent, skill,
tool, capability, or workflow mappings change.
