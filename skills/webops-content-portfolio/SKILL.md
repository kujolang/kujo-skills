# Webops Content Portfolio

## Purpose

Use this skill for assigning longitudinal content portfolio states. Its primary sources are ContentGraph, search, analytics, backlink, freshness, and business-purpose evidence.

## Workflow

1. Validate content identity and prior state.
2. Evaluate usefulness, accuracy, differentiation, relationships, demand, performance, and maintenance cost.
3. Assign CREATE, GROW, MAINTAIN, REFRESH, MERGE, REDIRECT, RETIRE, or IGNORE with rationale.
4. Record confidence, approval boundary, and next measurement.

## Required Output

- portfolio state.
- rationale.
- confidence.
- review horizon.

Every output must name target/scope, evidence class, retrieval or run time,
unavailable checks, permission mode, and comparison baseline where applicable.

## Boundaries

Portfolio state is a proposal, not an executed redirect or retirement. Preserve OBSERVE/PROPOSE/ACT boundaries, provider cost and credential
limits, stable finding identity, and the distinction among finding,
recommendation, action, and outcome. Never store credentials or fabricate
provider data, rankings, indexing, citations, compliance, or causation.

## Verification

Validate source artifacts with their owning tool before interpretation. Run
the current repository's WebOps cross-reference validation when agent, skill,
tool, capability, or workflow mappings change.
