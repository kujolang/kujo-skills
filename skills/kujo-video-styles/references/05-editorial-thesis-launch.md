# Editorial / Thesis Launch

## Job to be done

Launch an **idea** associated with Kujo.

Use when the thing being communicated is larger than a feature:

- Loop Engineering
- Jidoka
- Clarity / Context / Control
- “Trust at the speed of AI”
- agent operations
- solution factories
- a new architectural model

The video should feel like an editorial film or design manifesto, not a product tutorial.

## Core principle

A thesis film needs a progression of thought.

Do not make 12 inspirational title cards.

Every visual plate must either:

- introduce an idea
- create contrast
- provide evidence
- deepen the idea
- resolve the argument

## Narrative patterns

Choose one:

### Tension -> principle -> consequence
1. Current problem
2. Why common framing fails
3. Kujo principle
4. What changes when applied
5. Identity / CTA

### Old model -> new model
1. familiar assumption
2. breakdown
3. replacement model
4. implications
5. Kujo

### Question -> exploration -> answer
1. question
2. 2–4 evidence plates
3. synthesis
4. answer
5. identity

## Visual plate system

Build a small reusable vocabulary:

- oversized claim
- quote/evidence plate
- artifact close-up
- system diagram
- contrast plate
- code/terminal evidence
- principle wordmark
- brand identity frame

Each plate should have a distinct *purpose* but use a common grid, type system, and motion language.

## Typography

Typography may carry more of the film than in other formats.

Rules:

- hero copy generally <=8 words
- support copy generally <=20 words
- long quotes are discouraged
- avoid animating every word separately
- use typographic scale to encode argument hierarchy
- mono type should imply technical evidence, not be used decoratively everywhere

## Motion

Motion should be deliberate and editorial:

- slow push
- inverse zoom
- page/plate replacement
- crop reveal
- matched alignment
- restrained parallax
- occasional abrupt cut when it serves contrast

Fast glitch edits are allowed only when conceptually justified.

## Product evidence

Even a thesis film should contain some technical anchor.

For Kujo, that might be:

- a real agent trace
- a real gate blocking a bad outcome
- a diagram derived from actual architecture
- a real code artifact
- a measured result

This prevents the film from becoming vague brand poetry.

## Audio

- strong sound design
- VO optional
- music can be more cinematic/editorial
- pauses matter
- let major thesis statements breathe

## Acceptance criteria

- thesis can be written in one sentence
- each plate advances the argument
- no more than 2 consecutive purely abstract plates
- at least one concrete evidence beat when the concept concerns a real system
- typography remains readable on mobile
- no generic AI imagery
- no fake quote attribution
- no empty manifesto language
- ending connects the idea to a Kujo object, practice, or next action
