# Tool Launch Variant

- Treat each tool repository as independently installable, testable, documented, and releasable.
- Use its domain skill, `kujo-tool-building`, `kujo-security-hardening`, `kujo-cli-contracts`, and `kujo-loop-engineering-workflows` as applicable.
- Verify help, version, doctor, fixture mode, structured output, exit codes, safe path behavior, capability boundaries, schemas, examples, and release limitations.
- For a batch, maintain a matrix of repository, version, commit, tests, contracts, tag, release, site route, hero, social card, and final tree state.
- Publish tool pages under the canonical tooling catalog. Verify every GitHub link and keep shared catalog counts synchronized.
- Do not make one tool's release depend on unrelated batch members unless a documented shared contract requires coordinated release.
